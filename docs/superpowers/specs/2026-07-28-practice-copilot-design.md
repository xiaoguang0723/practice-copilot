# Practice Copilot 设计规范

## 1. 目标

在 Windows 10 2004+ 与 Windows 11 上提供一个本地模拟练习助手。应用以约五分之一屏幕面积的半透明悬浮窗运行，通过全局快捷键捕获主屏幕、调用用户配置的 OpenAI 兼容多模态模型，并将结果以 Markdown 流式展示。

成功标准：

- 应用启动后不出现在任务栏，只在系统托盘显示图标。
- 悬浮窗默认位于主显示器右下角，约 `460 × 620 px`，无边框、可拖动、始终置顶。
- Windows 内容保护默认开启；在遵守系统捕获排除机制的软件中，悬浮窗不出现在截图、录屏或屏幕共享结果中。
- `Alt+Q` 捕获整个主屏幕，`Alt+W` 发送最近截图并流式展示回答，`Alt+E` 显示或隐藏窗口，`Alt+X` 退出整个应用。
- 用户可配置 API Base URL、API Key、模型名与持久化提示词，配置在重启后保留。

## 2. 范围

首版包含 Electron 桌面外壳、React 界面、托盘、全局快捷键、主屏截图、内容保护、配置存储、OpenAI 兼容流式多模态请求和 Markdown 渲染。所有逻辑均在本机运行，不增加独立服务端、账户系统、遥测、自动更新、语音转写、知识库、历史会话或多显示器选择。

本项目参考 MeetingCopilot 的 Electron 主进程分层、受限 IPC、`safeStorage` 密钥保护和流式请求思路，但不复制其音频、ASR、知识库、会话和双栏界面。

内容保护属于尽力而为：它无法阻止摄像机拍摄、驱动级捕获、远程控制软件的特殊捕获路径，或刻意绕过 Windows 系统 API 的工具。产品文档不得宣称对所有截图和录屏软件绝对不可见。

## 3. 技术架构

- **运行时**：Electron 41、React 19、TypeScript、electron-vite。
- **主进程**：创建窗口与托盘，注册快捷键，调用 `desktopCapturer`，持久化配置，持有并解密 API Key，发起模型请求，将流式事件转发给渲染层。
- **预加载层**：在 `contextIsolation: true`、`nodeIntegration: false` 下暴露最小、强类型的 IPC API；渲染层不能访问 Node、文件系统或原始 IPC。
- **渲染层**：实现 A 方案单页界面、设置页、截图状态、请求状态、Markdown 增量展示和错误提示。
- **本地存储**：普通配置写入 Electron `userData` 下的 JSON 文件；API Key 使用 `safeStorage`（Windows DPAPI）加密后写入。渲染层只接收 `apiKeySet`，永不接收明文密钥。

窗口参数固定为 `frame: false`、`transparent: true`、`backgroundColor: '#00000000'`、`alwaysOnTop: true`、`skipTaskbar: true`。创建后调用 `setAlwaysOnTop(true, 'screen-saver')` 与 `setContentProtection(true)`。初始位置按主显示器 `workArea` 计算，距右侧和底部各 24 px；用户拖动后的窗口位置在下次启动恢复，并在显示器变化后夹紧到可见工作区。

应用使用单实例锁。关闭窗口等同于隐藏到托盘，只有托盘“退出”、`Alt+X` 或系统退出流程才终止进程。托盘菜单提供“显示/隐藏”“设置”“退出”；单击托盘图标切换窗口显示状态。

## 4. 界面设计

主窗口采用深色半透明单页专注布局：

- 顶部为可拖动标题栏，显示产品名、最近截图状态和设置按钮；交互控件标记为不可拖动区域。
- 中部为可滚动答案区，支持标题、列表、表格、引用、行内代码、代码块和复制文本。流式输出期间显示低干扰光标，不显示额外的“AI 正在工作”文案。
- 底部为临时提示词文本框。该内容只附加到下一次 `Alt+W` 请求，不自动发送；发送成功后保留，便于连续使用。
- 设置页覆盖在当前窗口内，包含 Base URL、API Key、模型名、持久化提示词和四个快捷键。API Key 输入框默认为空并以“已保存”状态提示，留空保存表示保留旧值，显式“清除密钥”才删除。

视觉使用 `rgba(15, 23, 42, 0.88)` 主背景、低对比边框、蓝色强调色、圆角与轻微模糊。窗口不依赖系统阴影，保证透明窗口边缘一致。主界面保持可调整大小，最小 `380 × 440 px`，最大尺寸不限制但始终夹紧在可见工作区。

## 5. 快捷键与截图流程

默认快捷键：

| 功能 | 默认值 | 行为 |
| --- | --- | --- |
| 捕获主屏幕 | `Alt+Q` | 捕获主显示器完整画面，覆盖内存中的上一张截图 |
| 发送解题 | `Alt+W` | 使用最近截图发起一次新的流式多模态请求 |
| 显示/隐藏 | `Alt+E` | 在保留当前状态的前提下切换窗口可见性 |
| 退出应用 | `Alt+X` | 取消请求、注销快捷键、销毁托盘并退出进程 |

快捷键允许在设置页修改。保存时先验证 Electron accelerator 格式，再尝试以全量事务方式重新注册：任何一个快捷键冲突或注册失败，都恢复旧快捷键并返回明确错误，避免配置与实际注册状态不一致。

`Alt+Q` 使用 `screen.getPrimaryDisplay()` 获取主显示器 ID、物理像素尺寸与缩放比例，再通过 `desktopCapturer.getSources({ types: ['screen'] })` 选择匹配源。截图转为 JPEG Data URL，质量设为 85，以降低请求体积；内存中只保留最近一张，不写入磁盘。成功后标题栏显示“已捕获”和时间，失败时保留旧截图并显示错误。

`Alt+W` 需要存在截图且模型配置完整。若已有请求正在流式返回，新请求会先取消旧请求再启动，答案区切换到新回答。请求期间不自动显示窗口，也不改变当前可见状态。

## 6. 模型接口与提示词

首版只支持 OpenAI 兼容的 `POST {baseUrl}/chat/completions`，Base URL 保存时移除末尾斜杠；若用户输入已经以 `/chat/completions` 结尾则直接使用，避免重复拼接。请求使用 `Authorization: Bearer <API Key>`、`Content-Type: application/json` 和 `stream: true`。

消息由以下内容按固定顺序组成：

1. `system`：内置的练习解题规则，要求先给结论、再给推理步骤，并对编程题提供复杂度与可运行代码。
2. `system`：用户在设置中保存的持久化提示词；为空时省略。
3. `user`：由文本“请分析截图中的题目并给出答案”、底部临时提示词，以及一张 `image_url` 类型的 JPEG Data URL 组成。

流式解析兼容标准 SSE：忽略空行与注释行，解析所有 `data:` 事件，收到 `[DONE]` 后结束，从 `choices[0].delta.content` 追加文本。HTTP 非成功状态、无效 JSON、服务端错误事件、网络中断和空回答均转换为统一错误事件。使用 `AbortController` 支持新请求替换旧请求与应用退出取消。

## 7. IPC 契约

预加载层暴露以下语义接口：

- `settings.get()`：返回公开配置与 `apiKeySet`。
- `settings.save(patch)`：验证并保存配置；`apiKey` 仅允许从渲染层单向传入主进程。
- `settings.clearApiKey()`：清除加密密钥。
- `capture.primary()`：执行一次主屏截图，返回捕获时间与尺寸，不返回图片内容。
- `answer.start({ extraPrompt })`：使用主进程保存的最近截图启动请求，返回 `requestId`。
- `answer.cancel(requestId)`：取消当前请求。
- `answer.onEvent(callback)`：订阅 `delta`、`done`、`error` 事件，并返回取消订阅函数。
- `window.hide()`、`window.toggle()`、`app.quit()`：执行受控窗口操作。
- `hotkeys.onAction(callback)`：接收截图、发送、切换与退出动作；渲染层只处理需要更新 UI 的截图和发送事件。

所有 IPC handler 对输入长度与类型做运行时验证。持久化提示词和临时提示词各限制 8,000 字符，Base URL 仅接受 `http:` 或 `https:`，模型名限制 200 字符。

## 8. 状态与错误处理

渲染层状态分为 `idle`、`captured`、`streaming`、`complete`、`error`。截图状态与回答状态独立：一次回答失败不会丢失最近截图，可以直接重试。设置未完成、没有截图、快捷键注册失败和模型请求失败都显示在窗口内的非阻塞提示条；错误消息不包含 API Key、完整请求体或图片 Data URL。

设置文件不存在或损坏时回退到默认值并保留损坏文件供诊断；写入采用临时文件加原子替换。`safeStorage` 不可用时拒绝保存 API Key并提示用户，不以明文或简单混淆方式降级。

主进程记录最小开发日志：窗口生命周期、快捷键注册结果、截图尺寸、请求状态和脱敏错误。生产版不记录提示词、答案、密钥或图像内容。

## 9. 测试与验收

单元测试覆盖设置合并与加密、URL 规范化、快捷键事务注册、SSE 分片解析、消息组装、输入验证和错误脱敏。React 测试覆盖主界面状态、流式追加、Markdown 渲染、设置保存和常见错误提示。

Windows 手工验收覆盖：

- 冷启动后只有托盘图标，没有任务栏按钮；窗口在主显示器右下角且始终置顶。
- 四个默认快捷键在窗口显示和隐藏状态下均生效；退出后全部注销。
- `Alt+Q` 捕获主屏幕且不落盘；连续捕获只保留最新截图。
- `Alt+W` 对标准 OpenAI 兼容服务产生多模态流式请求，Markdown 内容边接收边显示。
- 设置重启后保留，渲染进程无法读取明文 API Key。
- OBS 的 Windows Graphics Capture、Windows 截图工具和主流会议共享在受支持捕获路径下不显示悬浮窗；同时在 README 中保留内容保护能力边界说明。
- 缩放比例为 100%、125%、150% 时截图尺寸正确，窗口不会移出可见工作区。
- API 超时、401、429、500、无效 SSE、网络中断、缺少截图和快捷键冲突均给出可恢复反馈。

## 10. 默认假设

- 项目名与目录名为 `practice-copilot`，首版界面语言为简体中文。
- 目标平台仅 Windows x64；不在首版支持 macOS、Linux、ARM64 或商店发布。
- 采用 npm 与 `package-lock.json`，Node.js 最低版本为 20。
- 首版仅维护一张内存截图和一条当前答案，不保存截图或回答历史。
- 内容保护始终开启，不在设置中提供关闭开关。
